# LPライティングスキル(lp-writing)

## 前提として読むもの

`lp/<slug>/02-structure.md`(`lp-structure`の成果物)と、その元になった`01-research.md`を
必ず読む。構成にない要素を書き足したり、リサーチにない数字・実績を作ったりしない。
`02-structure.md`に「要確認」と書かれたセクションは、コピーもその旨が分かる形で書く
(例: 料金セクションは「ご相談のうえ決定/まずは無料相談へ」のような、確定前でも成立する
書き方にしておく)。

## まえちゃんの文体(reel-scriptと共通する部分)

- 一人称。「〜なんだ」「〜だよね」寄りのタメ口と、「〜ませんか?」「〜します」の丁寧語が
  混ざるのが地の喋り方。無理に統一しない
- 専門用語は使ってよいが、その場で必ず噛み砕く(例:「許容応力度計算」→「柱や梁を緻密に計算する」)
- 「肯定するだけで終わらない」姿勢がまえちゃんの信頼の源泉。業界の都合の悪い話も隠さず書く

## リールとの違い(ここを混同しない)

reel-scriptは**声に出して読む逐語原稿**で、装飾記号を一切使わない。LPは逆に
**画面を上から下にスキャンしながら読まれる**媒体なので、視覚的な区切りを積極的に使う:

- 見出し・小見出しを使ってよい(構造化された文章として書く)
- 箇条書き・チェックリストを使ってよい(特に「共感」セクションの悩みの列挙)
- 太字で要点を強調してよい。ただし1段落に太字が3つ以上あると逆に読みにくくなるので、
  「ここだけは見出しを読み飛ばしても伝わってほしい1点」に絞る
- 1文の長さはリールほど短く切る必要はないが、スマホの画面幅で3行を超える文は分割を検討する

## セクションごとのコピー作法

### キャッチコピー(ファーストビュー)
「誰の・どんな悩みを・どう解決するか」を1文に凝縮する。抽象的な美辞麗句(「理想の住まいを、
あなたに。」のようなもの)は避け、`01-research.md`の「表面の悩み」を具体的に指す言葉を入れる。
複数案を作り、**並べるだけで終わらせず推奨案まで決める**。

### 共感セクション
`02-structure.md`で列挙した悩みを、施主が自分の言葉で頷けるレベルまで具体化する。
「見積書の内訳が不安」ではなく「見積書に『一式』ばかりで、何にいくらかかっているか
分からないまま契約しそうになっていませんか?」のように、実際の場面を描く。

### 問題提起セクション
不安を煽って終わらせない。reel-scriptと同じく、損失を時間の長さで表現すると刺さる
(「数千万円払って後悔する家に何十年も住み続けることになる」型)。ただし**このセクションの
最後、または次のセクションの冒頭で必ず希望に転換する**(「でも、着工前ならまだ全部間に合います」)。

### 解決策・サービス内容セクション
「住宅会社とケンカする必要はない」というまえちゃんのスタンスをここでも一貫させる。
施主が明日から使える具体的な行動(reel-scriptの「明日そのまま言えるセリフ」の発想)を
1つでも入れられると、読み手が自分ごと化しやすい。

### 権威性・お客様の声セクション
実績・数字は`01-research.md`にあるものだけを使う。ここで新しい数字を作らない。
お客様の声は匿名化ルール(氏名・地域・住宅会社名を特定できる書き方をしない)を
`lp-research`と同じ基準で守る。

### 料金・FAQセクション
料金が未確定な場合、断定した金額を書かない。「まずは無料相談で」「ご相談内容に応じてご案内」
のような、確定前でも嘘にならない書き方にする。FAQは申込みの心理的ハードルを下げる質問
(「他社と契約済みでも使えますか」等)を優先する。

### CTA文言
ボタン文言は動詞から始め、行動のハードルの低さが伝わる言葉にする(例:「無料相談に申し込む」
「まずは話を聞いてみる」)。LP内の複数のCTAボタンで文言・導線がズレないようにする
(`02-structure.md`で確認した本命の導線に統一)。

## 出力フォーマット

`lp/<slug>/03-copy.md` に、`02-structure.md`のセクション順のまま、各セクションの見出し・
本文・CTA文言を書く。HTML化・デザインは`lp-builder`(または`design`スキル)が行うので、
ここではプレーンテキスト+Markdownの強調(`**太字**`・箇条書き)だけで表現する。

```markdown
# LPコピー: <サービス名> (<slug>)

## 1. ファーストビュー
- キャッチコピー(候補と推奨案):
  - 候補A: ...
  - 候補B: ...
  - **推奨: 候補A**(理由: ...)
- サブコピー: ...
- CTAボタン文言: ...

## 2. 共感
(本文)

...(以下、構成のセクション順に続ける)
```

## 心構え

複数案を出すときは並べて終わりにせず、目的に照らして推奨案まで決める。構成やリサーチが
薄いままコピーだけ頑張って書いても良いLPにはならないので、素材が足りないと感じたら
`lp-research`や`lp-structure`に戻ることを提案してよい。
