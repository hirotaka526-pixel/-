# note記事スキル(note-article)

まえちゃんのnote記事を書く。

## 参照ファイル

本体は「記事の中身の作り方」。次は必要になったときに読む。

- `references/note-playbook.md` — 媒体側の作法(タイトル・見出し画像・目次・ハッシュタグ・
  公開設定・回遊)。**公開設定を決めるとき、見出し画像やタグを聞かれたときに必ず読む**
- `references/paid-article.md` — 有料記事の設計(有料にすべきかの判断・noteの手数料と価格上限・
  無料部分の切り方・価格の決め方)。**「有料にできる？」と聞かれたら、書き始める前に必ず読む**

## このスキルの一番大事な前提

noteは **読む媒体** であって、喋る媒体ではない。リールは1〜2秒で止められるかの勝負、
YouTubeは川下さんとの掛け合いで最後まで飽きさせない勝負だが、noteは違う。

- 読者は検索やSNSから「今まさに困っている状態」で流れ込んでくる
- スクロールで戻れるので、**手順・チェックリスト・例外** といった、動画では流れてしまう情報が価値になる
- 契約前の人が **家族に見せる・住宅会社との打ち合わせに持っていく** ことがある。だから断定と例外の
  バランスを、動画より一段慎重に取る

リールの台本をそのまま貼り付けるのはやらない。話し言葉のままだと読みにくく、
リールで削ぎ落とした「例外」「手順」「根拠」が抜けたまま残るため、記事としては薄くなる。

分量の目安は **2,500〜4,000字**。これより短いと検索から来た人が物足りず、
長いと最後のCTAまで読まれない。

## まえちゃんの立場(記事で曲げてはいけない前提)

本人が繰り返し発信している立場がある。**一般論に薄めない。** 特に構造まわりは以下の通り。

- **インザホームは全棟で許容応力度計算をしている。** 「性能表示計算でも等級3は取れます」という
  書き方は本人の立場ではない。3つの計算方法を説明した上で、自社がどれをやっているかを言い切る
- **「耐震等級3相当」は認めない。** 制度上存在しない造語であり、耐震性が確認されていない家だと
  本人は判断している。「相当にも真面目な会社はある」といったフォローを勝手に足さない
- **耐震等級1は違法ではない。** 2025年4月に義務化されたのは構造計算書の提出であって、
  耐震等級3にすることではない。ここを混同した記事は本人が出せない

一般論としてバランスを取りにいくと、**本人が書いていない記事になる。** 判断が分かれる論点では、
「私は〜と判断しています」「私は〜だと思っています」の形で、意見であることを示したまま言い切る。
これなら強さと誠実さが両立する。

線引き(⑥のブロック)は必ず書くが、**主張を打ち消す線引きは書かない。** 書くのは
「等級1を選ぶこと自体は違法ではない」「計算しても地盤と施工で決まる部分がある」「費用はかかる」
のような、主張と両立する範囲の但し書きに限る。

新しいテーマで立場が分からないときは、書く前に本人に聞く。推測で穏当な側に寄せない。

## 記事の型

ブロックの順番は入れ替えない。「結論を先に出して、根拠と手順で支える」構成にする。

**① タイトル**
- 検索される言葉(見積書、一式、耐震等級3、C値、地盤改良 など)を必ず1つ以上入れる
- 「1級建築士が」「現場から」など、誰が言っているかが分かる語を入れる
- 煽りだけのタイトル(「知らないと大損」だけで中身が分からない)にはしない
- 案を3つ出して、推奨を1つ決めて渡す

**② リード(200〜400字)**
- 「〜と言われて、そのままサインしようとしていませんか」と、読者の今の状況を名指しする
- この記事で何が分かるのか、読んだあと何ができるようになるのかを書く
- 「着工前ならまだ間に合います」のような、希望を先に出す一文で締める

**③ 結論(この記事で一番言いたいこと)**
- 見出しの直後に1〜2文で言い切る。根拠は後ろで説明する
- ここまでを読んで離脱した人にも、一番大事な一言だけは持ち帰らせる

**④ なぜそうなるのか(現場の話)**
- 数字と具体例で説明する。「電気工事 一式 80万円」のように、実際の見積書に出てくる文言で書く
- 20年以上現場に立っている人にしか書けない話(着工後に何が起きるか、職人がどう動くか)を必ず1つ入れる。
  ここが他のブログとの差になる

**⑤ 読者が明日できること(手順・セリフ)**
- 番号付きの手順、または **そのまま住宅会社に言えるセリフ** の形で渡す
- 「ケンカする必要はありません」と、角を立てずに頼む言い方であることを添える

**⑥ 例外と、やりすぎない線引き**
- 「ここまで細かく言う必要はありません」という線を必ず書く
- 動画では尺の都合で1点しか書けないが、noteでは2〜3点書ける。ここが記事の信頼をつくる

**⑦ まとめ(3〜5行の箇条書き)**
- 読者がスクショして打ち合わせに持っていける形にする

**⑧ CTA(定型。毎回この形で入れる)**

本文の最後に18大特典の一言を置き、「正しい知識を身につけて、賢く理想の家づくりをしましょう。」で
本文を締める。そのあとに、見出し付きのCTAブロックを2つ、この順で置く(下記をそのまま使う)。

```
こうした家づくりの基準は、プロフィールのリンクからお渡ししている豪華18大特典でも
解説しています。よければ受け取ってください。

正しい知識を身につけて、賢く理想の家づくりをしましょう。
```

## noteで読まれる書き方

型(次章)に沿っていても、文章の質感が違うと読まれない。noteで反響が出ている記事は次の形をしている。

- **相談の場面から入る。** 「先日、相談に来られたご夫婦がいました」のように、実際にあった会話から
  始める。制度の説明から始めない。読者は自分と同じ立場の人の話で引き込まれる
- **会話をそのまま書く。** 「この"相当"って、どういう意味か聞かれましたか？」のように、
  短いセリフを地の文に混ぜる。臨場感が出て、専門的な話が読み物になる
- **段落は2〜3文で切って、1行空ける。** スマホで読まれるので、詰まった文章は飛ばされる。
  ここぞという一文は、1行だけの段落にして独立させる
- **感情を隠さない。** 「この言葉のせいで、〜する人があまりに多いからです」のように、
  なぜ怒っているのかを書く。事実だけを並べた記事は最後まで読まれない
- **見出しだけ拾って読んでも意味が通るようにする。** 見出しに結論を入れる
  (×「計算方法について」 ○「『等級3相当』という等級は、どこにも存在しません」)
- **最後に自分の言葉で締める。** 「私は、お客さんの家をそこに預けたくないんです」のような、
  立場が出る一文を必ず1つ入れる。ここが読者に残る

## 文体

- 一人称は「私」。リールの「〜なんだ」「〜だよね」というタメ口は、noteでは **多用しない**。
  丁寧語をベースにして、力を入れたい一文だけタメ口に落とすと、地の喋り方が残ったまま読みやすくなる
- 1文は短く。読点で3つも4つもつながない
- 専門用語は使ってよいが、初出でその場で噛み砕く(例:「許容応力度計算」→「柱や梁を1本ずつ計算する方法」)
- 見出しは `##`(必要なら `###` まで)。noteの見出しスタイルにそのまま乗る。
  記事の冒頭(リードの直後)にnoteの目次ブロックを入れるので、**見出しはそれ単体で意味が通る文にする**。
  「結論：」のようなラベルは付けない(目次に並んだときに読みにくい)
- 太字は1つの見出しに1〜2か所まで。多用すると全部が目立たなくなる
- **見積書の話で「行」と書かない。「項目」と書く。** 「1行ずつ比べる」→「1項目ずつ比べる」。
  読者は紙の行数ではなく工事の項目を見ている
- **並列するものは箇条書きにする。** 「コンセントが何個か。照明は何台か。配線は何か所か」と
  地の文で並べず、`・`で改行して並べ、疑問形で終える
- **短い文は句点で終えずに改行で切る。** 「〜からです」「〜だけです」のような一文は、1行1文で
  置いていくとリズムが出る。段落にまとめない
- **セリフは行を分ける。** 「ここにもコンセントが欲しい」「ここは調光にしたい」は改行して縦に並べる
- 番号付きの手順は `1、` `2、` `3、` と全角読点で書く(noteの自動番号と衝突しない)
- 「いかがでしたでしょうか」「〜と言えるでしょう」といった、書き手の顔が見えない定型句は使わない
- 表は使わない。noteの表は読みにくく、スマホで崩れる

## リールとの使い分け

同じネタをリールとnoteの両方で出すのはむしろ推奨。ただし役割を変える。

| | リール | note |
|---|---|---|
| 論点 | 1つ | 2〜3つ |
| 目的 | 止めさせて存在を知ってもらう | 検索から来た人に信頼してもらう |
| 例外の扱い | 一番反発が来そうな1点だけ | 2〜3点きちんと書く |
| 手順 | セリフ1つ | 手順+セリフ+チェックリスト |

リールを先に作っている場合は、その台本(`reels/`)を読んでから書く。**リールで使った具体例と数字は
そのまま使い、noteでは「その先」を足す。** 別々の数字を出すと、両方見た人が混乱する。

## ネタ選びとリサーチ

**ネタは既存の発信から持ってくる。**

- YouTube: https://www.youtube.com/@inthehome (「1級建築士 まえちゃんの家づくり教室」)
- 既存のリール台本: リポジトリの `reels/`
- note: https://note.com/inthehome_maeda (公開済みの記事は書き出しと導線の見本になる)
- 相談で実際によく出る質問

**リサーチは2段構えでやる。省略しない。**

1. **ネタ元の中身を確認する** — WebSearch / WebFetch で実際の動画・記事に当たる。
   タイトルから内容を推測して書かない
2. **数字と制度の裏取り** — 記事はリールと違って後から検索で読まれ続ける。古い数字が残ると害が大きい。
   特に次は年度で変わる:
   - 補助金・助成金(子育てグリーン住宅支援事業など)
   - 建築基準法・省エネ基準の改正(例: 2025年4月施行の4号特例縮小)
   - 長期優良住宅・耐震等級の申請費用、証紙代
   - 地震保険の割引率、住宅ローン控除、金利

   確認できた数字には、記事中に **いつ時点の情報か** を書く(「2026年8月時点」)。
   確認できなかった数字は記事に入れず、「ここは実感ベースの金額を入れてください」とメモで返す。
   ネットに繋がらない・裏が取れない場合は、**その数字を使う記事にしない** か、
   年度で変わらない論点(見積書の読み方、契約前の確認手順など)に振り替える。

ネタが指定されずに「note記事書いて」とだけ言われたら、**候補を2〜3個提案して推奨を1つ決め、
確認を取ってから書く**。ただし「おまかせ」と言われたら、推奨のテーマで書き切ってから
「他の候補はこれです」と添える。候補出しで止めて手ぶらで返さない。

## 納品の形

**記事1本につき、リポジトリの `notes/` に1ファイル。**

```
notes/YYYY-MM-DD-テーマ.md
```

ファイルの中身は **noteの編集画面にそのまま貼れる状態** にする。

- 1行目にタイトル(`# タイトル`)
- 本文の見出しは `##`
- 記事末に「見出し画像の方針」「本文中の写真差し込み位置」「ハッシュタグ案」は入れない
  (貼り付け時に消す手間になる)。これらは **チャット側で伝える**

チャットで一緒に渡すもの:

- タイトル案3つ(推奨つき)
- 見出し画像に入れる文言の案
- 本文中で現場写真を入れたい位置(「④の電気工事の話のあと」など)
- ハッシュタグ案(5個程度。#注文住宅 #家づくり #一級建築士 など)
- 数字の出典と、実感に合わせて差し替えてほしい箇所

Googleドキュメントにも残したい場合は、リール台本と同じく1本1ファイルで
`note記事：タイトル名`(コロンは全角)の名前で作る。NotebookLMのソースとして溜めるため、
**一度作ったドキュメントは作り直さない**。中身の修正は本人にドキュメント上でやってもらう。

## 公開後にやること

**公開版を必ず `notes/` に取り込む。** まえちゃんは投稿前に必ず手を入れる。その差分が、
このスキルの一番の教材になる。

1. 公開された本文をもらったら、`notes/` のファイルを公開版で上書きし、冒頭に公開日とURLを残す
2. 直された箇所を洗い出し、**書式・言い回しのルールとして再利用できるものは、このSKILL.mdに書き戻す**
   (例: 「行」→「項目」、箇条書き化、改行の細かさ、CTAの実物)
3. 一度きりの言い回しの好みは書き戻さない。次も効くルールだけを残す

これをやらないと、毎回同じ直しをさせることになる。

## 公開前チェック

- タイトルに検索される言葉が入っているか
- リードだけで「自分向けの記事だ」と分かるか
- 結論が前半に出ているか。最後まで読まないと結論が分からない構成になっていないか
- 数字は最新か。時点を書いているか
- 特定の会社・人が特定できる書き方になっていないか
- 例外・線引きを2〜3点書いたか
- 読者が明日できることが、手順かセリフの形になっているか
- CTAが2つ(プロフリンクの18大特典 / LINE相談)入っているか
- 2,500〜4,000字に収まっているか
- 同じネタのリールがあるなら、具体例と数字が食い違っていないか

## 心構え

まえちゃんは肯定するだけのアシスタントを求めていない。ネタが弱い、論点が多すぎる、数字が怪しい、
と思ったら遠慮せず指摘してから改善案を出す。複数案を出すときは並べて終わりにせず、推奨まで決める。

書いたあと、必ず自分で「これは家づくり検討中の人が、打ち合わせに持っていける記事か」を確認する。
持っていけないなら、手順とセリフが足りていない。
