# noteという媒体で読まれるための作法

記事の中身(構成・文体)はSKILL.md本体にある。ここは **媒体側の設定と作法** をまとめたもの。
書き終わったあと、公開設定を決めるときに読む。

**この文書の数字は2026年8月時点。** noteの仕様は変わるので、料率・上限・画面名を記事や
案内に書くときは、その都度確認してから使う。

## タイトル

- 対象読者が検索しそうな言葉を必ず1つ以上入れる(note内検索とGoogleの両方に効く)
- スマホの一覧表示で途切れない長さに収める。長くなるなら句読点や「｜」で区切る
- カナや漢字が続くと読みにくいので、ひらがなを混ぜて視認性を上げる
- 「｜1級建築士が〜」のように、誰が言っているかを後半に置くのがこのアカウントの型

## 見出し画像

**note公式が投稿データで、見出し画像がある記事はPV・スキが数十%高いと明言している。**
特別な理由がない限り全記事に付ける。

- 記事の内容と一致させる。内容と無関係なイメージ写真は逆効果
- 文字を入れるなら1〜2フレーズまで。一覧で縮小表示されるので、小さい字は読めない
- 現場写真・図面・実物の書類は、この業種では強い。フリー素材より圧倒的に目を引く
- サイズは横長。推奨サイズはnoteの投稿画面に表示されるので、そこで確認する

## 目次

- リードの直後に目次ブロックを入れる。見出しから自動生成される
- **目次に並ぶ項目は5〜7個が読みやすい。** 見出しを増やしすぎると目次が長くなって効果が落ちる
- 見出しはそれ単体で意味が通る文にする(「結論：」のようなラベルを付けない)
- CTAブロックの見出しも目次に載る。載ってよい(最後まで行かずに導線へ飛べる)

## ハッシュタグ

- 5個程度。多すぎると1つあたりの効果が薄れる
- 「#注文住宅」「#家づくり」のような母数の大きいタグと、「#耐震等級3」のような
  絞り込まれたタグを混ぜる。前者は流入、後者は濃い読者
- 毎回同じタグを3つ固定して、残り2つを記事ごとに変えると、過去記事への回遊が生まれる

## 公開設定まわり

- **予約投稿ができる。** 書き上げた時間に出さず、読まれる時間に合わせる
- マガジンにまとめる。家づくりの基礎知識シリーズとして束ねると、1本読んだ人が次を読む
- 記事末に関連する過去記事のリンクを1〜2本置く。noteは記事間の回遊で滞在が伸びる

## Googleドキュメントからnoteへの貼り付け

ドキュメントは `contentMimeType: text/markdown` で作るので、**見出しは見出しスタイル、
太字は太字、リンクはリンクとして入る。** そのままコピーしてnoteに貼れば書式ごと移る。

手順:

1. ドキュメントを開き、**1行目のタイトルを除いて**本文を選択してコピー
   (タイトルはnoteのタイトル欄に手入力する)
2. noteの本文にそのまま貼り付ける(`Ctrl+V` / `⌘+V`)。書式を保持して貼られる
3. リードの直後に**目次ブロック**を挿入する
4. 見出し画像を設定する

**noteに文字サイズを変える機能はない。** 大きさで強弱を付けたいときは見出しにする。
本文で使えるのは、太字・見出し・引用・区切り線・箇条書きだけ。
だから記事の設計段階で「ここは見出し」「ここは太字」を決めておく。

貼り付けが崩れたときの直し方:

- 見出しが本文になってしまった → その段落を選択してnoteの見出しボタンで付け直す
- フォントや色が浮いている → いったん `Ctrl+Shift+V`(書式なし貼り付け)で貼り、
  見出しと太字をnote上で付け直す。長い記事だと手間なので、まずは通常の貼り付けを試す

### 大きく書き直したときのドキュメントの扱い

原則は「一度作ったドキュメントは作り直さない」(NotebookLMのソースが切れるため)。
ただし **公開前で、まだNotebookLMに登録していない下書き**を全面的に書き直した場合は、
新しいドキュメントを作ってよい。そのとき:

1. 古いドキュメントは **タイトルを「【旧・削除してください】…」に変更**して区別する
2. 新しいドキュメントを標準の名前で作る
3. 本人に、古いほうを削除してもらう

**公開済み・NotebookLM登録済みのドキュメントは、絶対に作り直さない。** 本人に上書きしてもらう。

## 公開後

- 反応が良かった記事は、リールやYouTubeのネタに戻す。逆方向も同じ
- 公開版は必ず `notes/` に取り込む(SKILL.md「公開後にやること」参照)
