# LP構成スキル(lp-structure)

このフェーズでは文章を書かない。**どのセクションを、どの順番で、何の目的で置くか**だけを決める。
ここで骨組みが甘いと、`lp-writing`が良い文章を書いても全体としてちぐはぐなLPになる。

## 前提として読むもの

`lp/<slug>/01-research.md`(`lp-research`の成果物)を必ず読んでから始める。無ければ先に
`lp-research`を実行するよう促す。「要確認」が残ったままだと構成の一部(特に料金セクション・
特典セクション)が仮組みになるので、その旨を明記して進める。

## 家づくりサポートLPの標準セクション構成

これはたたき台であり、リサーチ内容によって統合・削除してよい。ただし順番の意図(不安を煽って
放置しない→解決策→信頼→行動のハードルを下げる)は崩さない。

1. **ファーストビュー**
   - キャッチコピー(1文で「誰の・どんな悩みを・どう解決するか」)
   - サブコピー(補足)
   - 信頼バッジ(1級建築士/インザホーム代表など、パッと見て分かる肩書き)
   - 第一CTAボタン(スクロールしない人向けに、ここにも申込導線を置く)

2. **共感(こんな悩みありませんか)**
   - `lp-research`の「表面の悩み」を3〜4個、チェックリスト形式で並べる
   - 1つでも当てはまれば続きを読む理由になる、という作り

3. **問題提起(放置するとどうなるか)**
   - 「裏にある不安」を具体化する。reel-scriptの「損失を時間の長さで表現する」型
     (例: 数千万円払って後悔する家に何十年も住み続けることになる)は静止読みのLPでも効く
   - ここで終わらせず、次のセクションで必ず希望を出す(不安だけで終わると離脱する)

4. **解決策の提示(家づくりサポートとは)**
   - サービスの一言要約
   - 「住宅会社とケンカする必要はない」「着工前ならまだ間に合う」など、reel-scriptで
     磨かれてきた核となるメッセージをLPでも軸にする

5. **サービス内容**
   - 提供形式・回数・期間など、`01-research.md`で確認できた仕様をそのまま反映
   - 未確認の項目があるセクションは「(要確認: 料金確定待ち)」と明記して`lp-writing`に渡す

6. **権威性・実績**
   - プロフィール、資格、フォロワー数・登録者数、施工/相談実績
   - Instagram/YouTubeで普段の発信を見ている見込み客向けに、「知ってる人」感を出す導線
     (実際のリールやYouTube動画へのリンクを置くのもあり)

7. **お客様の声**
   - `01-research.md`にある実例。数が少ない場合はこのセクションを短くする・後回しにする
     判断をしてよい(無理に埋めない)

8. **料金・プラン**
   - 料金が未確定なら、このセクションは「相談してから決まる」形にするか、
     「まずは無料相談で」に寄せるかを`lp-research`の要確認事項と照らして判断する

9. **よくある質問(FAQ)**
   - 「他の住宅会社と契約済みでも使えますか」「工事中でも間に合いますか」など、
     申込みの心理的ハードルを下げる質問を優先する

10. **最終CTA**
    - LP全体で一番強い訴求。申込導線は`01-research.md`で確認した本命(LINE公式など)に統一する
    - ファーストビューのCTAと文言・導線を揃える(片方はLINE、片方はフォーム、のようなズレを作らない)

11. **法的表記**
    - 申込み・料金が絡むLPなので、特定商取引法に基づく表記(運営者・連絡先・返金条件など)や
      プライバシーポリシーへの導線が必要かどうかを確認する。必要な場合は末尾に置く場所だけ確保し、
      具体的な文面は本人・専門家の確認が要る旨を`lp-check`に引き継ぐ

## セクションの取捨選択の判断

情報が薄いセクション(お客様の声が無い、実績数が出せない等)を無理に埋めない。以下のどちらかを選ぶ:

- **統合する**(例: 権威性と実績を1セクションにまとめる)
- **弱めに置く**(例: お客様の声が1件しかないなら、大きな見出しにせず権威性セクションの中で触れる)

情報が薄いまま大きなセクションとして構成してしまうと、`lp-writing`が中身のない文章で
埋めることになる。構成の段階で「ここは弱い」と正直に判定するのが、この担当の仕事。

## 出力フォーマット

`lp/<slug>/02-structure.md` に以下の形でまとめる:

```markdown
# LP構成: <サービス名> (<slug>)

## セクション一覧
1. ファーストビュー
   - 狙い: ...
   - 入れる要素: ...
   - 参照(01-research.mdの該当箇所): ...
2. 共感
   - ...
(以下同様。統合・削除したセクションはその理由も書く)

## 全体の流れで意識したこと
- ...

## 料金・法的表記まわりの保留事項
- ...(要確認のまま構成に反映した箇所)
```

## 次に渡すときの注意

`lp-writing`はこのファイルの「入れる要素」を見てコピーを書く。ここで狙いを具体的に
書いておくほど、次のコピーがブレなくなる。「共感セクション」とだけ書いて渡さず、
「表面の悩み3つをチェックリストで」まで書く。
