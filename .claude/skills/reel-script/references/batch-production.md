# 複数本まとめて作るときの進め方

「リール台本を◯本作りたい」のように、まとめて依頼されたときの進め方。1本ずつ、次の4ステップを踏む。
単発で「1本作って」と言われたときはこのファイルは不要(通常のネタ選び→writingの流れでよい)。

## 全体の流れ

0. 本数が決まったら、まず**全テーマの候補を先に全部出して確定させる**。1本作ってから次を考える、
   という場当たり的な進め方はしない。`reels/neta-bank-*.md`(ネタ帳バンク)があれば出現回数順に出す。
   なければyoutube-scriptスキルの過去動画やYouTube/noteから出す。
   候補を出す前に、Googleドライブの「リール台本」フォルダ内の既存タイトルに目を通し、
   似たテーマがあれば切り口を変えるか候補から外す。「これは既存の◯◯と重なるので外した」と
   一言添えると、ユーザーが選ぶ基準が分かりやすい。
1. **テーマを決める** — 候補を複数出し、推奨を1つに絞って提示する。ユーザーが選ぶ、または差し替える。
2. **壁打ち・提案** — フック2行、使える材料、構成案をラフに出す。この時点ではまだ逐語で書き込まない。
3. **手直し** — 本人からの直し(表現、数字の正確性、ニュアンス)を受けて調整する。
4. **ドキュメントに記載** — 確定した台本を、納品フォーマット通りにGoogleドキュメントへ書く
   (1本1ファイル、タイトルは「リール台本：〜」、保存先は「リール台本」フォルダ)。

1本片づいたらテーマ2に進む。4本ぶんを一気に書き上げて後からまとめて直す、という進め方はしない
(手直しの意図が次の本に反映されないまま量産すると、同じ指摘を何度もやり直すことになる)。

## センシティブなテーマが出てきたとき

紹介手数料のように「話したいが、業界内で角が立つ・法的にグレーに見える」テーマが候補に挙がることがある。
このとき、いきなり台本を書き始めない。一度立ち止まって次の順で進める。

1. リスクを2種類に分けて説明する。
   (a) 名指しした相手からの反発・法的リスク
   (b) 視聴者から「結局ポジショントークだろう」と受け取られるリスク
   多くの場合、実務上の危険は(a)より(b)のほうが大きい。まず(b)を指摘する。
2. リスクを避けて発信できる型を提案する。例: 特定の相手を名指ししない、批判ではなく
   仕組みの解説に振る、自分の利害関係を言われる前に自分から開示する。
3. 最終判断は本人に委ねる。「言いたいけど見送る」も普通の判断としてそのまま受け止め、
   翻意を促さない。
4. 見送る場合も、テーマ自体をネタ帳から消さない。「見送りの理由」と「やるときの条件」を
   書き添えて残す。気が変わったときにゼロから考え直さずに済むし、条件が記録されているので
   後で扱うときも同じ検討をやり直さずに済む。

## 単一テーマ深掘り構成の実験・2週目バッチ(本人指定・2026-10-09)

1週目(2026-09-30、7本)の結果が出る前に、本人の意向で2週目バッチも単一テーマ深掘り構成で
継続することになった。「1本ずつ壁打ちしていきたい」という進め方の指定あり。

ネタ選びの過程で学んだこと(次回以降のテーマ選定に反映):
- **リフォーム単体テーマは反響が悪い**(本人指摘・2026-10-09)。リフォーム関連の法改正
  ネタなどを提案する際は避ける、または別の角度を主役にする
- **土地系テーマは視聴が伸びにくい傾向**(本人指摘・2026-10-09)。土地系を扱うときは
  フックの強度(逆張り・常識破壊)を特に上げる必要がある
- 同じ論点(例: 耐震等級3)を2本で扱うのはNG。壁打ち段階で候補同士の重なりを本人が
  自分で指摘して弾いた(⑦「壁量計算vs許容応力度計算」は④「地震保険半額」と同じ耐震の
  話のため却下)
- **簡単・面白い比喩で説明を圧縮する路線**を本人が自作の見本台本(「家づくりの見積もり、
  完全に『ぼったくりバー』だった件」)で提示。②③のようなユーモア系フックとは別に、
  本編全体を1つの比喩(ぼったくりバーの「席料」「高級ボトル」「夢のショールーム」)で
  通すスタイル。ただし①(市街化調整区域)に試したところ「分かりにくくなった」という
  理由で撤回された。**比喏が合うかどうかはテーマによる**ので、毎回本人に確認してから
  本編に適用する。また調査で出てきた古い制度・歴史的経緯(既存宅地制度の廃止など)は
  台本に入れない、今の情報と今すぐできる対処に絞る、という方針も明確になった

## CTA無し構成の実験(本人指定・2026-10-10)

2週目バッチ⑤(クロスSP/AA級)で、本人がGoogleドキュメント上で【75-85s：今すぐできる
行動】と【85-100s：信頼の伴走＆CTA】を直接削除し、結論で終わる構成に変更した。

- 狙いは視聴維持率。毎回CTAを入れると売り込み臭が強くなるという判断
- 対象の選び方: テーマ自体が「家づくりの終盤にいる人」向けで、LINE相談やサポートを
  今すぐ必要としていないと判断できるテーマ(クロス・仕上げ系など)でCTA無しを試す。
  序盤〜中盤向けのテーマ(土地・契約前・構造判断など)は通常通りCTAを入れる
- 結果次第で、週の投稿の半分程度をCTA無しにすることも本人が検討中
- 次回以降の週次分析で、CTA無し投稿の視聴維持率を他のCTA有り投稿と比較する
- ネタ帳バンクに「CTA無し」と記録しておき、週次分析で振り返れるようにする

## シェア(送信)狙いの実験(本人指定・2026-09-20)

複数の外部情報で「2026年のInstagramアルゴリズムは保存よりシェア(DM送信)を重く
評価する」という指摘があった(裏取り未了)。これを踏まえ、保存率だけでなく
シェア数も指標に加える実験を開始した。

- 実験の変数は1つ: 台本の末尾に「パートナーや友達に送ってあげて」という
  明示的なシェア誘導の一文を追加する。他の構成・フックは変えない
- シェアが狙いやすいテーマ(夫婦間の意見の違い、友人に教えたくなる注意喚起など)を
  選ぶと、誘導文が自然になる
- ネタ帳バンクに実験対象の台本と変数を記録し、週次分析でシェア数の変化を追う

## CTA①の挿入位置は複数パターンをサンプル収集中(本人指定・2026-09-10)

CTA①(18大特典)を末尾ではなく本編の途中に前倒しする構成を試す際、本人は
「1投稿だけでは結果が正確に出ない」という理由で、**投稿ごとに挿入位置を
意図的に変えている**(1つ目の直後、2つ目の直後、など)。これは下の「1回に
1変数だけ」の原則の例外であり、位置そのものを複数サンプル集めて後で
比較するのが狙い。台本を作るたびにCTA①をどこに入れたかをネタ帳バンクに
記録し、週次分析で「位置別の成績」を振り返れるようにしておく。

## 実験は1回に1変数だけ(本人指定・2026-09-09)

台本の構成・冒頭フックのスタイル・尺などを、直近の勝ちパターン(週次分析で確認済みの
番号リスト構成・営業トーク引用/常識否定型フック・タイムスタンプ構成)から意図的に外して
試すときは、**変える点を1つだけに絞る**。冒頭とCTAを同時に変える、構成とフックを同時に
変える、といった複数変更は、どの変更が数字に効いたのか週次分析で切り分けられなくなる。

- 変えないのがデフォルト。特に理由がなければ、直近の勝ちパターンをそのまま使う
- 変える場合は「今回はフックのパターンだけを試す(構成・尺は据え置き)」のように、
  チャットで**変えた変数を明言**してから台本を出す
- Googleドキュメントの本文には実験メモを書き込まない(納品フォーマットを崩さない)。
  実験の意図はチャットでの説明のみで伝える

## テーマを決める前に、Googleドライブ全体で既出チェックをする(本人指定・2026-09-10)

`reels/neta-bank-*.md`(相談録から作ったネタ帳)の出現回数だけでは「既出だが成績が
悪かった」テーマを見抜けない。ネタ帳は相談録からの抽出であって、投稿履歴ではないため。

実際に「現場監督を見れば会社が分かる」を提案したところ、過去に3回近い言い回しで
既に投稿されており(`fullText contains`検索で発覚)、しかも成績が良くなかったことが
分かった。これを繰り返さないために:

- テーマを決める前に、必ず `mcp__Google_Drive__search_files` で `fullText contains`
  検索(テーマのキーワードで)をかけ、`リール台本` フォルダ以外(ルート直下や他の
  フォルダに散らばっている過去台本)も含めて既出でないか確認する
- 似た内容が見つかったら、提案する前に「これは過去に◯回投稿されているようです、
  結果はどうでしたか」と本人に確認する
- 「見送り」になったテーマは、ネタ帳バンクに理由と一緒に残す(削除しない)。
  同じ轍を踏まないための記録として扱う

## 同一テーマは1週間以上空ける(本人指定・2026-09-09)

同じ内容・同じテーマのリールを短期間に重ねて投稿したくない、という要望がある。
台本を提案する前に、直近7日以内に同じテーマ分類(例: 気密・性能、構造、間取り設計、
お金、営業トーク等)で作った台本がないか確認する。

- 判断材料は「Googleドライブのリール台本フォルダの作成日」と、このリポジトリの
  `reels/`配下のファイル名(日付入り)
- 該当があれば、同じ分類のテーマは避けて別分類から選ぶか、本人に「直近で扱ったばかりなので
  別テーマにします」と一言添えて切り替える
- ネタ帳バンク(`reels/neta-bank-*.md`)にテーマ分類のタグがあれば付けておくと、
  次回以降この確認が速くなる
