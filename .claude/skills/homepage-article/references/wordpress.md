不要と言われたため。納品の主役は **Googleドキュメント（本文＋図の挿入位置）＋

## Markdownに書く指示コメント

本文のMarkdownに直接書く。これで図・写真・ボックスの位置が決まる。
**wp.html生成はしなくなったが、このコメント記法は記事の構成メモとして今後も使う**
（どの段落がボックスで、どこに図が要るかを自分で見失わないため）。

| 書き方 | 効果 |
|---|---|
| `<!-- fig: キー -->` | figures.py の該当図。Googleドキュメントではこの位置に「［図N：キャプション］」という1行プレースホルダーとして書く |
| `<!-- photo: 説明 \| alt \| ファイル名 -->` | 写真が要る位置のメモ（まえちゃんに別途撮影を頼む） |
| `<!-- box: crit\|warn\|good\|info \| ラベル -->` | 直後の段落が「注意ボックス」相当の内容だという構成メモ |
| `<!-- sns: 導入文 -->` | 中盤のYouTube導線を入れる位置 |
| `**テキスト**` | 強調したい語句 |

### ボックス相当の内容の使い分け(色は使わないが、構成としては維持する)

| 種類 | 使いどころ |
|---|---|
| `crit` | 「こう答える会社は要注意」— 危ないサイン |
| `warn` | 年度で変わる制度の但し書き、注意事項 |
| `good` | やるべきこと、良い状態の説明 |
| `info` | 「この記事で分かること」などの案内 |

**1記事につき crit 相当の強い注意喚起は2〜3個まで。** 増やすと効かなくなる。

## 図解の書き方

`articles/<slug>.figures.py` に、次の形で書く。

```python
from svg_kit import *          # 共通部品と検証済みパレット

def fig_example():
    W, H = 880, 400            # 幅は必ず 880（STD_W）
    s = []
    s.append(txt(0, 28, '図の言いたいこと', 17, INK, '700'))
    s.append(box(0, 50, 420, 300, TINT, LINE))
    ...
    return wrap(''.join(s), W, H,
                'スクリーンリーダー用のタイトル',
                '図の内容を文章で説明したもの')

FIGURES = {'example': (fig_example, '図1：キャプション')}
```

### 守ること

- **幅は880固定で描く。** PNG書き出し時にドキュメント用の表示幅(480〜620px程度)へ
  縮小する。元を880で描いておけば、縮小しても文字がにじまない
- **色は `svg_kit` の定数だけを使う。** 新しい色を足さない
  （dataviz スキルの検証済みパレットに揃えてある）
- **`wrap()` の title / desc を必ず書く。** 図の内容を文章で言い切れるかの確認にもなる
- **色だけで意味を伝えない。** ✓／✕／ラベルを必ず添える
- 図中の文字は16px以上、注記でも13px以上（880幅の描画時点でのサイズ。縮小後も
  判読できるように、この余裕を削らない）

### 図解が向くテーマ

- **2つのものの比較**（壁量計算と許容応力度計算、瑕疵保険と完成保証、一式と内訳明細）
- **段階・順序**（断熱等級、家づくりのスケジュール）
- **体制・流れ**（設計と施工の分業／一貫）

数字が主役でない限り、棒グラフや円グラフにしない。住宅記事で本当に必要なのは
**「どっちがどう違うのか」を1画面で見せる比較図**。

### 図解の内容を疑うこと

図は本文より強く記憶される。だから **本文が正確でも図が言いすぎていたら図の負け。**
たとえば「壁量計算では基礎を検討しない」は誤り（仕様の基準はある）。
正しくは「1棟ごとの個別計算はしない」。**断定する前に必ず裏を取る。**

## PNG書き出しの解像度

`export_png.py` は既定でSVGのviewBoxをそのまま2倍解像度（幅1760px前後）で書き出す。
これはWordPress時代にSVGが除去される環境向けのフォールバックとして作った経緯があり、
**Googleドキュメントに貼る用途には解像度が高すぎてファイルが重い。** ドキュメントへの
貼り付け用に渡すときは、480〜620px幅程度に縮小したものを別途書き出して渡す
（縮小方法は `export_png.py` の実装を参照。target幅を変えて呼び出す）。

## Googleドキュメントへの入れ方

1. 記事本文をMarkdownで書く（フロントマターにSEO納品セット、本文に指示コメント）
2. 指示コメントを取り除いた「読める本文」を作る。**`<!-- fig: キー -->` の位置には、
   何を貼ればいいか一目で分かるプレースホルダー行を残す。**

   ```
   ［図1：住宅完成保証と瑕疵担保責任保険が対象とする期間の違い］
   ```

3. 著者プロフィールボックス・SNS・関連記事を末尾に追加する（テンプレートは
   `seo-checklist.md` の該当セクション）
4. `mcp__Google_Drive__create_file` で `contentMimeType: text/markdown` として作成する
   （**画像は埋め込まない。理由はSKILL.mdの「なぜGoogleドキュメントに画像を自動で
   埋め込まないのか」を参照**）
5. 図解PNG（480〜620px幅に縮小したもの）を `SendUserFile` でまえちゃんに送る。
   キャプションに「どのプレースホルダーに対応するか」を明記する
   （例:「図1：住宅完成保証〜の図です。同名のプレースホルダーの位置に貼ってください」）

**一度作ったドキュメントは作り直さない。** プレースホルダーの入れ忘れに気づいても、
後から本文だけを差し替える手段が無いので、作成前に指示コメントの位置を見直しておく。
