# WordPress納品の作り方

記事本文を書いたら、**必ず**この手順で装飾つきHTMLまで作る。Markdownのまま渡さない。
まえちゃんはWordPressのコードエディターに貼るだけで公開できる状態を求めている。

---

## 手順

```bash
S=.claude/skills/homepage-article/scripts

# 1) 図解を書く(記事ごとに1ファイル)
#    articles/<slug>.figures.py  … svg_kit を import して FIGURES 辞書を作る

# 2) 装飾つきHTMLを生成
python3 $S/build_wp.py articles/<slug>.md articles/<slug>.wp.html articles/<slug>.figures.py

# 3) 実際に描画して目で見る(省略禁止)
python3 $S/preview.py articles/<slug>.wp.html /tmp/prev 0 1600 3200

# 4) SVGが除去される環境向けにPNG版も出す
python3 $S/export_png.py articles/<slug>.figures.py articles/figures/
```

**3を飛ばさないこと。** 色が破綻していないか、図の文字が潰れていないか、
モバイルで本文が横に溢れていないかは、描画して見るまで分からない。
特に **390px幅のスマホ表示は必ず確認する。**

## Markdownに書く指示コメント

本文のMarkdownに直接書く。これで図・写真・ボックスの位置が決まる。

| 書き方 | 効果 |
|---|---|
| `<!-- toc -->` | 目次ブロックのプレースホルダ |
| `<!-- fig: キー -->` | figures.py の該当図を挿入（キャプションは図側が持つ） |
| `<!-- photo: 説明 \| alt \| ファイル名 -->` | 写真プレースホルダ（黄色の点線枠） |
| `<!-- sns: 導入文 -->` | 中盤のYouTube導線ボックス |
| `<!-- box: crit\|warn\|good\|info \| ラベル -->` | 直後の段落を色つきボックスに |
| `<!-- cards -->` | 直後の番号付きリストを丸数字カードに |
| `<!-- muted -->` | 直後の箇条書きを控えめな色に |
| `==テキスト==` | 黄色マーカー |
| `**テキスト**` | 太字（ブランド色） |

フロントマターに `タイトル:` `スラッグ:` `関連記事:` を書くと、タイトル欄の文字列と
記事末の関連記事リンクが自動で作られる。**著者プロフィールボックスとSNSボタンは自動で付く**
ので、本文に手書きしない。

### ボックスの使い分け

| 種類 | 色 | 使いどころ |
|---|---|---|
| `crit` | 赤 | 「こう答える会社は要注意」— 危ないサイン |
| `warn` | 黄 | 年度で変わる制度の但し書き、注意事項 |
| `good` | 緑 | やるべきこと、良い状態の説明 |
| `info` | 青 | 「この記事で分かること」などの案内 |

**1記事につき crit は2〜3個まで。** 増やすと赤が効かなくなる。

## 装飾の仕様（勝手に変えない）

すべてインラインstyleで書き出す。テーマのCSSに左右されないため、どのWordPressでも同じ見た目になる。

| 要素 | 仕様 |
|---|---|
| H2（大見出し） | 濃紺 `#0d366b` 背景に白抜き・23px・角丸6px |
| H3（中見出し） | 「質問N：」形式ならバッジつきカード。それ以外は下線つき・20px |
| 本文 | 17px／行間1.95／`#1a1a19` |
| 太字 | ブランド色 `#0d366b` |
| マーカー | `linear-gradient(transparent 62%, #ffe89a 62%)` |
| 図解 | 白背景・薄枠・角丸、横スクロール容器つき |
| 著者ボックス | 濃紺2px枠＋薄青背景 |
| SNSボタン | YouTube `#c4302b` / Instagram `#b4318f` |

ブランドカラーを変えるときは `build_wp.py` 冒頭の `BRAND` 系の定数だけを書き換える。
本文側に色を直書きしない。

## 図解の書き方

`articles/<slug>.figures.py` に、次の形で書く。

```python
from svg_kit import *          # 共通部品と検証済みパレット

def fig_example():
    W, H = 880, 400            # 幅は必ず 880（STD_W）
    s = []
    s.append(txt(0, 28, '図の言いたいこと', 17, INK, '700'))
    s.append(box(0, 50, 420, 300, TINT, LINE))
    ...
    return wrap(''.join(s), W, H,
                'スクリーンリーダー用のタイトル',
                '図の内容を文章で説明したもの')

FIGURES = {'example': (fig_example, '図1：キャプション')}
```

### 守ること

- **幅は880固定。** `svg_kit.wrap()` が `min-width:660px` を付けるので、
  スマホでは横スクロールになり文字が潰れない
- **色は `svg_kit` の定数だけを使う。** 新しい色を足さない
  （dataviz スキルの検証済みパレットに揃えてある）
- **`wrap()` の title / desc を必ず書く。** スクリーンリーダーが読む唯一の情報源
- **色だけで意味を伝えない。** ✓／✕／ラベルを必ず添える
- 本文の文字は16px以上。注記でも13px以上

### 図解が向くテーマ

- **2つのものの比較**（壁量計算と許容応力度計算、瑕疵保険と完成保証、一式と内訳明細）
- **段階・順序**（断熱等級、家づくりのスケジュール）
- **体制・流れ**（設計と施工の分業／一貫）

数字が主役でない限り、棒グラフや円グラフにしない。住宅記事で本当に必要なのは
**「どっちがどう違うのか」を1画面で見せる比較図**。

### 図解の内容を疑うこと

図は本文より強く記憶される。だから **本文が正確でも図が言いすぎていたら図の負け。**
たとえば「壁量計算では基礎を検討しない」は誤り（仕様の基準はある）。
正しくは「1棟ごとの個別計算はしない」。**断定する前に必ず裏を取る。**

## PNGフォールバック

インラインSVGは、マルチサイトやセキュリティプラグインの設定で除去されることがある。
`export_png.py` で2倍解像度のPNGを書き出し、`articles/figures/` に置いて納品する。
入稿手順書には「図が消えていたらPNGに差し替え」と必ず書く。
