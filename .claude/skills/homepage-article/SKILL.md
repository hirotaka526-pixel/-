# ホームページ記事スキル(homepage-article)

インザホームのホームページ(https://inthehome.jp)に載せる記事を作る。

## このスキルの一番大事な前提

**記事本文だけでは納品完了ではない。** 本文と一緒に、下の「SEO納品セット」を必ず全部渡す。
本文だけ渡して「SEOも必要なら言ってください」と付け足すのは、このスキルでは失格。
まえちゃんはSEOを意識した記事を求めているので、最初から全部入りで出す。

リール台本(逐語原稿だけを渡す)、YouTube台本(ネタ帳+サムネ文言)とは納品物がまったく違う。混同しない。

## 事業と発信の前提(記事の軸になるので毎回踏まえる)

- 会社: 有限会社 IN THE HOME(インザホーム) / 愛知県高浜市向山町5丁目9番17
- 代表: 前田浩貴。1級建築士・1級建築施工管理技士・2級土木施工管理技士
- **売りは3つ。記事のどこかで必ず伝わるようにする**
  1. **建築士がやっている会社** — 営業マンではなく、資格を持った建築士が直接プランを描く
  2. **自由に設計できる** — 規格住宅・企画型ではなく、暮らしに合わせて一から設計する
  3. **建築士が現場も管理している** — 設計した人間がそのまま現場を見るので、設計と施工が分断されない。
     図面通りに建つ。ここが「技術力のある会社」であることの一番の根拠
- ただし **売り込みを前面に出さない。** 記事は読者の疑問を解決するのが仕事で、
  上の3つは「だから設計と施工を同じ建築士が見ている会社かどうかを確認してください」のように、
  読者にとっての判断基準の形で自然に混ぜる

## 扱うテーマ

消費者が実際に検索して悩んでいることを扱う。専門家が語りたいことではない。

- 注文住宅(費用、土地探し、会社選び、契約、スケジュール)
- 住宅性能(耐震等級、断熱等級、UA値、許容応力度計算、長期優良住宅)
- 間取り(動線、収納、後悔ポイント、平屋、家事ラク)
- 気密(C値、気密測定、換気、結露)
- お金(見積書の読み方、補助金、住宅ローン、諸費用、坪単価)

まえちゃんは知識を詰め込みすぎる傾向がある。**1記事1テーマ。** 論点が増えたら別記事に回して内部リンクでつなぐ。

## 進め方

### ステップ1: テーマとキーワードを決める

テーマが指定されていなければ、候補を2〜3個提案して決めてもらう。いきなり書き始めない。

決まったら **主軸キーワードを1つ**、サブキーワードを2〜4個決める。主軸は必ずローカル修飾を検討する
(例:「注文住宅 費用」ではなく「高浜市 注文住宅 費用」)。

### ステップ2: 競合調査(必ずやる。省略しない)

**検索ボリュームツール(キーワードプランナー等)はこの環境にはない。数字を捏造しない。**
代わりに WebSearch で実際に何が上位に出るかを調べ、次を確認する。

- 上位10件が **全国ポータル(SUUMO/ホームズ/ハウスメーカー)で埋まっているか**
  → 埋まっていたら、そのキーワードは正面から取りに行かない。ローカル修飾かロングテールに逃がす
- 上位記事のタイトル・見出しに何が書かれているか → 同じことを書いても勝てない。
  **現場の実務者にしか書けない切り口**(実測値、実例、判断基準、業界の内側)を必ず1つ以上入れる
- 競合の文字数感 → それを上回る情報密度にする

ボリュームについて言及するときは「推定」と明記し、根拠(サジェスト有無、関連質問の量、
競合の厚さ)を添える。断定しない。

### ステップ3: 記事を書く

- **お役立ちコラム**(/column/): 3,000〜5,000字。検索流入狙いの解説記事。これが標準
- **社長ブログ**(/blog/): 1,200字前後。現場の出来事や業界への本音。SEOは軽めでよいが、
  地域名と著者プロフィールボックスは入れる

構成の型:

1. **リード(200〜400字)** — 読者の悩みを言語化 → よくある通説を否定 → 誰が書いているか(1級建築士・
   現場管理まで)→ この記事で分かることを予告。主軸キーワードと地域名をここに入れる
2. **目次(TOC)** — H2見出しから自動生成する想定で、原稿には目次を入れる位置だけ指定する
3. **本文** — H2で章、H3で小見出し。**H3はできるだけ「質問文」の形にする**
   (強調スニペット・「他の人はこちらも質問」に拾われやすい)
4. **地域の話を最低1か所** — 西三河・知多の地盤、気候(夏の暑さ、伊勢湾からの風)、
   土地相場など、その土地でしか書けないことを1段落入れる。ローカルSEOで一番効く
5. **まとめ + CTA**
6. **著者プロフィールボックス**
7. **関連記事(内部リンク)**

### ステップ4: SEO納品セットを全部そろえる

`references/seo-checklist.md` に各パーツの書き方と文字数の型がある。**書き始める前に読む。**

### ステップ5: 納品

## SEO納品セット(これが全部そろって初めて納品)

| # | 納品物 | 要点 |
|---|--------|------|
| 1 | 記事本文 | 上の構成。主軸キーワードはH1・リード・H2の1つ・まとめに入れる。詰め込みすぎない |
| 2 | **titleタグ** | **32文字前後**(全角)。記事のH1見出しとは別に作る。主軸キーワード + 地域名 + 数字/ベネフィット。「｜インザホーム」は文字数を圧迫するので入れるか要判断 |
| 3 | **meta description** | **120文字前後**。誰の何の悩みに、この記事が何を答えるか。キーワードを自然に含める。クリックされる約束を書く |
| 4 | **URLスラッグ** | 半角英小文字+ハイフン。3〜5語。日本語URLにしない(例: `takahama-cvalue-kimitsu`) |
| 5 | **内部リンク設計** | 発リンク3〜5本。既存記事「家づくりで失敗しないための間取りの考え方」(`/column/madorinokanngaekata/`)は間取り・後悔系の記事から必ずつなぐ。アンカーテキストは「こちら」ではなく記事の内容が分かる文言にする。**まだ無い記事へのリンクを提案するときは「未作成」と明記する** |
| 6 | **FAQPage構造化データ** | 記事内のQ&A(H3の質問文)から3〜6問を抜き、JSON-LDでそのまま貼れる形で渡す。**本文に書いていないQ&Aを入れない**(Googleのガイドライン違反になる) |
| 7 | **目次(TOC)** | H2/H3の階層で提示。WordPressのプラグイン任せでも、原稿側で見出し構造を整えておく |
| 8 | **画像指示とalt** | 3〜5枚。何の写真/図解が要るかを指定し、alt文を書く。altにキーワードを詰め込まない。自社施工写真を使うことを前提に書く(フリー素材だと信頼が落ちる) |
| 9 | **著者プロフィールボックス** | 記事下に置く。E-E-A-Tの直球なので毎回入れる。定型文は `references/seo-checklist.md` にある |
| 10 | **SNS導線** | Instagram・YouTubeへの誘導文。下記のルールに従う |

## SNS導線(毎回入れる)

高浜市周辺での認知拡大が目的なので、記事から必ずSNSに流す。

- **YouTube**: 「1級建築士 まえちゃんの家づくり教室」 https://www.youtube.com/@inthehome
- **Instagram**: https://www.instagram.com/in.the.home/

置き方:

- **記事の中盤**(本文が一番盛り上がったあたり)に1か所。「この話はYouTubeでも詳しく解説しています」
  のように、**そのテーマに関係する動画へ誘導する**。関係ない動画に飛ばさない
- **記事の最後**にもう1か所。プロフィールボックスの下に、YouTube・Instagram両方を並べる
- 動画のタイトルやURLが分からない場合は、`[該当動画のURLを入れてください]` とプレースホルダーを置き、
  チャット側で「ここに入れる動画を選んでください」と伝える。**存在しない動画タイトルを書かない**

## 数字と制度の裏取り(reel-scriptと同じルール。省略しない)

台本と同じく、記事に出す数字は必ず最新を確認してから書く。特に年度で変わるもの:

- 補助金・助成金(みらいエコ住宅2026事業など)
- 建築基準法・省エネ基準の改正(2025年4月施行の省エネ基準適合義務化、4号特例縮小)
- 長期優良住宅・耐震等級の申請費用
- 住宅ローン控除、金利、地震保険の割引率

確認できなかった数字は記事に入れず、「ここは実感ベースの金額を入れてください」とチャットで伝える。
記事はリールと違って残り続けるので、古い数字を書くと後で効いてくる。**年度が変わる制度を書いたときは、
「YYYY年度の情報です」と記事内に明記する。**

## 納品の形

**記事1本につき、Googleドキュメントを1つ作る。** ファイル名は:

```
ホームページ記事：タイトル名
```

コロンは全角の「：」。リール台本(`リール台本：タイトル名`)と同じ命名ルール。NotebookLMのソースとして
溜めていくので、名前だけで何の記事か分かる状態を保つ。

- ドキュメントには **記事本文 + 著者プロフィールボックス + 関連記事** だけを入れる。
  そのままコピペで公開できる状態にする
- **titleタグ・meta description・スラッグ・FAQ構造化データ・画像指示・確認メモは
  ドキュメントに入れず、チャット側で渡す。** NotebookLMのソースに管理情報が混ざると邪魔になる
- **一度作ったドキュメントは作り直さない。** ソースがファイルIDに紐づいているため。
  中身を直す必要が出たら本人にドキュメント上で直してもらう(タイトル変更だけはこちらで対応可)
- 記事はリポジトリの `articles/` にも1本1ファイルで残す(`YYYY-MM-DD-slug.md`)。
  こちらにはSEO納品セットもフロントマターとして全部書いておく

## 公開前チェック

- titleタグは32文字前後に収まっているか。主軸キーワードが前半にあるか
- meta descriptionは120文字前後か。クリックする理由が書いてあるか
- 主軸キーワードを詰め込みすぎていないか(不自然に繰り返していないか)
- 地域名(高浜市 + 近隣)がリード・本文・まとめに自然に入っているか
- **その地域でしか書けない段落が1つ以上あるか**
- 現場の実務者にしか書けない切り口が1つ以上あるか(これが無いと競合に埋もれる)
- FAQ構造化データのQ&Aが、すべて本文に書かれている内容か
- 内部リンクのうち、未作成の記事へのリンクに「未作成」と印がついているか
- SNS導線が中盤と最後の2か所に入っているか
- 著者プロフィールボックスが入っているか
- 数字は最新か。年度が変わる制度に「YYYY年度の情報です」と書いたか
- 売り込みが前面に出すぎていないか(読者の判断基準の形になっているか)

## 心構え

まえちゃんは肯定するだけのアシスタントを求めていない。狙うキーワードが激戦すぎる、テーマが競合と
被っている、切り口が弱い、と思ったら **書く前に指摘する**。複数案を出すときは並べて終わりにせず、
推奨まで決める。

ホームページ記事は残り続けるので、リールより慎重に。断定しすぎない、古い数字を書かない、
特定の会社が特定できる書き方をしない。
